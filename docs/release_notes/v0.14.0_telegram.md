**pgmnemo 0.14.0 и 0.14.1 — что вышло**

Два релиза подряд, собираем в одном месте — в прошлых постах номера версий потерялись в тексте.

**0.14.0 — память, которая сама себя чистит.**

Память агента копится бесконечно: один и тот же сбой разбирают заново, каждый раз записывая новый урок. На реальном рабочем корпусе в 7 400 записей нашлось **399 групп дубликатов — четверть базы**; самая большая группа — 55 отчётов об одной и той же поломке.

• `consolidate()` — сворачивает группу почти одинаковых записей в одну каноническую и проставляет, сколько наблюдений её подтверждают. Связи сохраняются.
• `classify_content_type()` и `reclassify_corpus()` — раскладывают записи по типам: процедура, инцидент, решение, факт, сущность. Там, где 95% записей лежали в одном типе, разбор выделил 699 инцидентов и 647 решений — теперь их можно искать раздельно. Новые записи типизируются при вставке сами.

Обе функции по умолчанию работают в режиме dry-run: сначала показывают, что собираются сделать.

**0.14.1 — починили поиск и добавили откат.**

• `recall_hybrid()` на части запросов думал 22–30 секунд. Причина не в данных: размер выборки приходил в `LIMIT` через переменную, план строился заранее без её значения, и планировщик перебирал всю таблицу вместо индекса. Теперь число подставляется напрямую.
• `undo_consolidate()` — отмена свёртки дубликатов. В 0.14.0 операция была необратимой, и это была наша недоработка: инструмент, меняющий корпус, обязан уметь откатываться.

Обновление: `ALTER EXTENSION pgmnemo UPDATE TO '0.14.1';`

Для агентов в Claude Code, Codex и Gemini есть MCP-пакет — `pip install pgmnemo-mcp`, затем `pgmnemo init`.
