**Память, которая сама себя чистит**

Память агента копится бесконечно. Один и тот же сбой разбирают заново, каждый раз записывая новый урок — и через полгода в базе лежит гора почти одинаковых записей, а поиск достаёт из неё случайную.

Насколько всё плохо, видно на цифрах: в реальном рабочем корпусе на 7 400 записей нашлось **399 групп дубликатов — 1 897 записей, четверть базы**. Самая большая группа: 55 отчётов об одной и той же поломке.

**pgmnemo 0.14.0** добавляет два инструмента против этого.

**`consolidate()`** — находит группы почти одинаковых записей, выбирает в каждой каноническую и сворачивает в неё остальные, проставляя, сколько наблюдений её подтверждают. Связи со свёрнутыми записями сохраняются, ничего не теряется.

**`classify_content_type()` и `reclassify_corpus()`** — раскладывают записи по типам: процедура, инцидент, решение, факт, сущность. На том же корпусе, где 95% записей были свалены в один тип, разбор выделил 699 инцидентов и 647 решений — теперь по ним можно искать раздельно. Новые записи типизируются при вставке сами.

Обе функции по умолчанию работают в режиме **dry-run**: сначала показывают, что именно собираются сделать, и меняют данные только с явным флагом.

Обновление: `ALTER EXTENSION pgmnemo UPDATE TO '0.14.0';`
