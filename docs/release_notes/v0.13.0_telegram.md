<b>pgmnemo 0.13.0</b> — Outcome-Loop v2 + use-attribution

Большое обновление системы обучения на результатах: Байесовская уверенность вместо аддитивной дельты, атрибуция использования, фильтрация по качеству совпадений.

<b>Что нового:</b>

• <b>Posterior confidence (OL-v2).</b> Вместо аддитивных дельт (+0.10/−0.15) уверенность теперь вычисляется как среднее Beta-распределения: <code>(success + α) / (success + fail + α + β)</code>. Beta(1,1) — равномерный априорный. Предыдущая схема (OL-260605 вердикт: r_pb = −0.05, p = 0.66) заменена на проверенную на продакшн-данных (r_pb = +0.20, p = 0.008, 468 прогонов). По умолчанию <code>confidence_boost_weight = 0.0</code> — активируйте вручную для деплойментов со своим outcome-сигналом (инструкция в USAGE.md).

• <b>Use-attribution (p_used).</b> <code>reinforce(id, outcome, p_used)</code> — новый параметр. <code>p_used = FALSE</code>: урок показан, но не использован — не засчитывается. <code>TRUE</code> или <code>NULL</code> — засчитывается (обратная совместимость). Новая колонка <code>use_count</code> отслеживает подтверждённые использования отдельно от <code>recall_count</code>.

• <b>Фильтрация по score (p_min_score).</b> Все функции отзыва теперь принимают <code>p_min_score REAL DEFAULT NULL</code>. При <code>p_min_score =&gt; 0.40</code> отбрасываются уроки с <code>match_confidence &lt; 0.40</code> до ORDER BY/LIMIT — количество холостых токенов −34% по данным MEM_AB v2. По умолчанию NULL — поведение идентично 0.12.x.

<b>Также в 0.12.2 (включено):</b>

• Фикс <code>add_edge()</code>: ON CONFLICT падал при отсутствии индекса <code>uq_mem_edge_active</code> в некоторых путях установки.
• Дедупликация активных рёбер перед созданием уникального индекса (безопасно для prod).
• <code>guard_no_test_project()</code> теперь через GUC <code>pgmnemo.test_project_floor</code>.
