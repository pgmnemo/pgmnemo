**pgmnemo 0.14.2 — функция уборки больше не выкидывает чужое**

Нашли неприятное, пока обновляли собственную базу до 0.14.1.

`reclassify_corpus()` раскладывает записи по типам: процедура, инцидент, решение, факт, сущность. Проблема была в том, что она переписывала тип у **всех** записей подряд — включая те, чей тип проставлен явно другой командой. `remember_event()` пишет тип `event`, классификатор про такой не знает и спокойно менял его на свой.

На нашей базе холостой прогон показал: `event 10 → 0`. То есть повторный запуск уборки стёр бы весь слой эпизодов — записи о том, чем закончились прошлые запуски. Полезных правок в том же прогоне было десять штук. Обмен так себе.

Не применили только потому, что обе функции курации по умолчанию работают вхолостую и сначала показывают, что собираются сделать. Ровно тот случай, ради которого этот режим и делался.

**Что в релизе:**

• `reclassify_corpus()` трогает только записи, чей тип пустой или входит в набор, который классификатор сам умеет выдавать. Всё, проставленное явными командами, неприкосновенно. Защита выводится из самого классификатора, а не из списка исключений — значит новые типы будут защищены автоматически.
• `evidence_count` (сколько наблюдений подтверждают запись) теперь **накапливается** между запусками свёртки, а не перезаписывается. Раньше число показывало только последний прогон и противоречило собственному описанию.
• Плюс четыре мелких исправления по итогам ревью: слово «rejected» больше не тянет запись в решения, тест на границу между ролями наконец проверяет саму границу, добавлен тест отката сразу нескольких групп.

Обновление: `ALTER EXTENSION pgmnemo UPDATE TO '0.14.2';`
